# 디자인 시스템 UX 감사

2026-10-29 상위 모델이 기획 IA, 생성 시안, 갤러리 소스와 실행 화면을 대조했습니다. 독립 감사의 범위는 갤러리와 기획이며 제품의 전체 기능을 실사용 검증한 것은 아닙니다.

## 확인한 문제와 조치

| 문제 | 근거 | 상태 |
|---|---|---|
| 모바일 헤더의 제품명과 테마 버튼이 줄바꿈됨 | 375×812 실행 화면 | 보조 제목을 좁은 화면에서 숨겼습니다. Chrome 375px에서 제품명과 테마 버튼이 한 줄로 표시됨을 재확인했습니다. |
| 다크 모드에서도 색상표에 라이트 값이 표시됨 | 테마 전환 실행 및 갤러리 소스 | 테마별 표시 값을 분리하고 Chrome에서 다크 전환 후 텍스트와 색상 변경을 확인했습니다. |
| Pretendard 이름만 선언하고 글꼴을 제공하지 않음 | CSS와 파일 검사 | JHF Reader의 Pretendard Variable 파일과 OFL 라이선스를 복사했습니다. 로컬 글꼴 요청 200과 `document.fonts.check` 성공을 확인했으며 글리프별 실제 사용 글꼴은 미확인입니다. |
| 현재 섹션을 탐색 메뉴에서 식별할 수 없음 | 메뉴 코드와 실행 화면 | 선택 표시를 추가했습니다. 상위 모델이 하단 메뉴 클릭, 뒤로가기와 스크롤에 따른 변경을 확인했습니다. |
| 입력 오류가 표시된 후 포커스는 버튼에 남고 자동 음성 알림 여부는 미확인 | 실행 화면 및 입력 컴포넌트 | 오류 시 팀 이름 입력으로 포커스가 이동함을 Chrome에서 확인했습니다. 스크린리더 음성 안내는 미확인입니다. |
| 입력 컴포넌트가 전달받은 className과 접근성 속성을 덮어씀 | 공통 컴포넌트 코드 | 외부 className, aria-describedby, aria-invalid를 합성하도록 변경했습니다. 실제 제품 사용처 검증은 남았습니다. |
| 대화상자에 초대 취소 문구와 행동이 고정됨 | 공통 컴포넌트 코드 | 제목·내용·버튼을 전달하도록 변경했습니다. 진행·오류 상태를 포함한 실제 제품 흐름 검증은 남았습니다. |
| 진행·중복 제출 방지·실패 및 재시도 예시가 없음 | 공통 컴포넌트와 샘플 코드 | 실제 제품 이관 전에 각 흐름의 상태와 결과 확인 방식을 정해야 합니다. |
| 색상표·패널이 첫 화면을 차지하고 패널이 중첩돼 작업 요소의 위계가 약함 | 1265×712 및 375×812 실행 화면 | 버튼·입력을 앞에 두고 중첩 데모 배경을 줄였습니다. 시각적 완성도에 대한 사용자 평가와 전체 제품 적용은 남았습니다. |
| 다크 표면 역할의 문서 값과 코드 값이 일치하지 않음 | `DESIGN.md` 색상표와 `tokens.css` | 미해결. 역할을 확정하고 두 정본을 일치시켜야 합니다. |

## 제품 흐름과 구현 경계

### 후속 확인

같은 날 후속 검토에서 갤러리의 섹션 외곽 카드 반복을 구분선으로 바꾸고 탐색 배경을 밝게 조정했습니다. `DESIGN.md`의 색상표는 실제 `tokens.css` 변수명과 라이트·다크 값에 맞췄습니다. 각 테마의 색상 토큰 17개와 갤러리 목록 및 문서 값이 일치하는 것을 코드로 확인했습니다. 다크 갤러리에서 배경, 카드와 컨테이너의 표면 분리도 확인했습니다. 전체 제품 테마의 대비 및 접근성 검증은 별도 과제입니다.

기획의 출발점은 초대 → 로그인·가입 → 워크스페이스 합류 → PR 카드 → 홈입니다. 그다음 멤버 탐색 → 지원·스카우트 → 수락 → 팀 개요, 팀 개요 → 칸반 → 완료 요청·승인, 알림 → 해당 항목의 경로를 설계합니다. 각 흐름은 역할, 권한, 빈 상태, 만료·중복·실패·복구와 복귀 경로를 포함해야 합니다. 데스크톱의 워크스페이스 레일·컨텍스트 탐색과 작은 화면의 접히는 탐색은 기획을 기준으로 검토합니다.

이미지 시안의 메뉴·사람·지표는 실제 기능이나 데이터의 근거가 아닙니다. 현재 갤러리는 제품에 공통 컴포넌트를 이관하기 전의 샘플입니다. 백엔드 계약, 실데이터, 실제 모바일 기기, 스크린리더, 확대·축소, 모든 키보드 동선과 WCAG 전체 기준은 이번 감사에서 확인하지 않았습니다.
