## 정보 구조

```
/login · /signup · /forgot-password · /oauth/success      인증(셸 없음)
/invite/:inviteCode                                      초대 확인 → 참여
/empty-workspace                                         소속 없음: 초대 코드 참여 / 워크스페이스 만들기
/ws/:workspaceId                                         워크스페이스 홈(내 팀·다른 팀·멤버)
  /team-formation                                        팀 빌딩
  /team/:teamId                                          팀 공간(공지·칸반·게시판·캘린더)
  /chat/:chatId                                          DM·그룹 채팅
  /video/live?roomId=                                    화상회의
/my-page · /my-page/profile-edit · /my-page/account-settings · /users/:userId   계정·프로필
/notifications                                           알림(준비 중)
```

셸: 데스크톱은 워크스페이스 레일(워크스페이스 전환·만들기·참여·계정) + 컨텍스트 탐색(홈·팀 빌딩·팀·DM·그룹 채팅·화상회의) + 본문. 1024px 미만은 상단 막대 + 탐색 서랍.

## 시안과 실제 기능의 차이

시안에 있지만 백엔드 API가 없어 이번 리뉴얼에서 만들지 않는 것입니다. 가상의 데이터나 동작으로 채우지 않습니다.

| 시안 요소 | 상태 | 대신 하는 것 |
|---|---|---|
| 프로젝트 지원·스카우트, 지원자 승인 대시보드 | API 없음 | 팀 만들기·참여(`/teams`, `/teams/{id}/join`)와 기존 팀 빌딩 도구 |
| 알림 센터 목록·알림 설정 | API 없음 | 알림 화면은 준비 중 상태, 탐색에서 제외 |
| 홈의 오늘의 체크리스트·최근 활동·진행률 | 집계 API 없음 | 소속 팀·다른 팀·멤버만 표시 |
| PR 프로필 온보딩의 학교·학년·전공 | 필드 없음 | 기존 프로필 필드(MBTI·성향·선호/비선호 방식·포트폴리오·해시태그) |

## 발견한 문제(이번 단계에서 고친 것)

- 홈·팀·채팅 페이지가 셸과 별도로 사이드바를 한 번 더 렌더링해 채팅방·화상회의 API를 중복 호출했습니다.
- 초대 링크가 `/#/ws/코드`(해시 라우터 형식)라 BrowserRouter에서 열리지 않았습니다.
- 회원가입 클라이언트 검사가 서버의 특수문자 필수 규칙을 빠뜨려, 화면 검사를 통과해도 서버가 거절했습니다.
- `loadWorkspaces()`를 직접 호출해도 이미 로드됐다는 이유로 무시됐습니다(참여 후 갱신·재시도 불가).
- 401 처리 시 `location.hash`만 바꿔 로그인 화면으로 이동하지 않았습니다.
- 팀 빌딩 화면으로 가는 링크가 어디에도 없었습니다.

## 남은 위험과 확인할 것

- 백엔드 비밀번호 규칙이 가입(`!@#$%^&*()-=`, 대소문자 필수)과 재설정(`@$!%*?&`만 허용)에서 다릅니다. 화면은 각각 따르지만 서버 규칙을 하나로 맞추는 편이 좋습니다.
- 화상회의 목록 5초 폴링은 기존 동작을 유지했습니다. 서버 이벤트(SSE)로 바꾸는 것은 8단계에서 검토합니다.
- 검증은 목 API(Playwright 경로 가로채기)로 했습니다. 실제 백엔드·실기기·스크린리더 검증은 하지 않았습니다.
