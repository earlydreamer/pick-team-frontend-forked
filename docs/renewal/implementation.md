# 리뉴얼 프론트엔드 구현 기록

이 문서는 `docs/renewal`의 기획을 프론트엔드에 구현하는 진행 상황을 기록한다. 저장소에 GitHub 이슈 기능이 꺼져 있어서 단계 계획과 결정 사항을 이 문서와 각 PR 본문에 남긴다.

## 구현 원칙

### 기존 코드와의 관계

기존 화면 코드(`src/features`, `src/layout`, `src/components` 등)는 지우지 않고 참고용으로 둔다. 리뉴얼 앱은 `src/renewal`에 처음부터 작성하고, `index.html`은 리뉴얼 앱을 띄운다. 기존 코드는 빌드 진입점에서 빠졌지만 타입 검사 대상에는 남아 있다.

### 데이터 계층

화면은 `src/renewal/data/ports.ts`의 포트에만 의존한다. 백엔드 저장소에는 아직 리뉴얼 도메인(PR 카드 v2, 팀 빌딩 세션, 지원·스카우트)이 없으므로 지금은 목 어댑터(`src/renewal/data/mock`)가 포트를 구현한다. 백엔드 API가 생기면 같은 포트를 구현하는 http 어댑터를 추가하고 `src/renewal/data/index.ts`에서 교체한다.

목 어댑터는 브라우저 localStorage(`pickteam.renewal.mock`)에 데이터를 저장한다. 화면 상단의 "목업 데이터" 표시로 실제 데이터와 구분하며, 아바타 메뉴에서 수강생·강사·매니저 계정을 전환해 역할별 화면을 확인할 수 있다. localStorage `pickteam.renewal.mock.fail`에 작업 이름(예: `members,saveCard`)을 넣으면 해당 호출이 실패해 오류 상태를 확인할 수 있다.

서버 상태는 TanStack Query로 관리한다(종합 스펙 §5.4).

### 문서와 문구

화면 문구는 DESIGN.md의 UX 라이팅 기준에 따라 해요체로 쓴다. 문서, 코드 주석, 커밋 메시지, PR 본문은 한다체로 쓴다.

## R1 결정 사항

### 셸 구성

IA §2.1의 글로벌 헤더, WS 레일, 컨텍스트 내비를 구현했다. 반응형은 §2.2를 따른다. 1024px 이상에서는 레일과 내비를 고정하고, 768~1023px에서는 레일만 고정하고 내비를 드로어로 연다. 768px 미만에서는 드로어 안에 레일과 내비를 함께 넣는다.

### 컨텍스트 내비 항목

워크스페이스(홈, 멤버 카드, 팀 빌딩), 관리(대시보드, 세션 운영, 설정), 내 팀, 내 계정 순서로 그린다. 관리 섹션은 개설자와 매니저에게만 보인다. 팀 빌딩 항목은 세션이 없으면 숨기고, 모집 중이면 마감 D-day를 표시한다.

IA §2.3의 공지와 커뮤니케이션(DM, 그룹 채팅, 화상회의) 항목은 아직 넣지 않았다. 해당 화면을 구현하는 단계에서 추가한다. 목업 pr-card-edit.html을 따라 내 계정 섹션(내 PR 카드, 계정 설정)을 내비에 두었다.

### 목업 단계의 인증

실제 인증은 범위 밖이므로 목업 계정 전환으로 대신한다. 아바타 메뉴의 로그아웃은 인증 단계에서 추가한다.
